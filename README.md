# 손잡고 마중

유치원 귀가 관리 — 아이를 안전하게, 집으로.

회사 서버 한 곳에서 **여러 유치원**에 서비스합니다. 선생님들은 태블릿·휴대폰·PC 브라우저로
접속하며, 기기마다 설치할 것이 없습니다.

반·차량·차수·시각·학원·계정·원아는 모두 유치원별로 나뉘어 서로 섞이지 않습니다.

## 계정

| 역할 | 하는 일 | 만들어지는 방법 |
|---|---|---|
| **운영자** | 유치원 가입 승인·중지 | 서버를 세울 때 한 번 |
| **원장** | 선생님 계정 · 설정 · 원아 명부 | **가입 신청 → 운영자 승인** |
| **교사** | 출결 · 귀가 처리 | **원장이 만듦** |

가입은 원장만 신청합니다. 선생님 계정은 원장이 직접 만들고, 임시 비밀번호가 한 번
표시됩니다. 선생님은 **첫 로그인 때 본인이 비밀번호를 정합니다.**

그만두신 선생님은 지우지 않고 **「중지」** 합니다. 지난 인계 기록에 누가 처리했는지가
남아 있어야 하기 때문입니다.

## 무엇을 하는가

| 화면 | 내용 |
|---|---|
| 오늘 현황 | 반별 총원·결석·조퇴·귀가·현원, 차수별 진행, 지연 경고 |
| 귀가 명단 | 차수별 명단 — 지금 쓰는 구글시트 세 탭을 대신함 |
| 원아 명부 | 아이 한 명이 한 줄인 주간 귀가 계획 |
| 명부 엑셀 | 양식 내려받기 · 올리기 · 미리보기 후 등록 (원장) |
| 선생님 관리 | 계정 추가·수정·비밀번호 재발급·중지 (원장) |
| 감사 로그 | 누가 언제 무엇을 했는지 (원장·운영자) |
| 설정 | 반·차량·차수·시각·학원 (원장) |
| 유치원 운영 | 가입 승인·중지 (운영자) |

핵심은 **주간 계획 한 장에서 매일 명단이 자동으로 만들어진다**는 점입니다.
같은 이름을 요일마다 탭마다 다시 적을 필요가 없습니다.

## 실행

```powershell
# 서버를 처음 세울 때 — 운영자 계정 만들기
python -m firstout.main --operator admin:내비밀번호

# 시연용 유치원과 예시 원아 95명 넣기
python -m firstout.main --demo --open

# 평소 실행
python -m firstout.main

# 개발 (코드 고치면 자동 반영)
python -m firstout.main --reload --open

# 자료를 지우고 처음부터 다시 (주의)
python -m firstout.main --reset --demo
```

| 옵션 | 뜻 |
|---|---|
| `--demo` | 시연용 가상 원아 95명을 넣는다 |
| `--open` | 브라우저를 함께 연다 |
| `--reload` | 코드를 고치면 서버가 자동으로 다시 읽는다 |
| `--reset` | 자료를 모두 지우고 처음부터 |
| `--operator 아이디:비밀번호` | 운영자 계정 생성 (한 번만) |
| `--port 9000` | 다른 포트로 |

시연 계정: `wonjang` (원장) · `teacher1` (교사) — 비밀번호 `majung1234`

### 테스트할 때

주간 계획은 월~금 기준이라 **주말에는 명단이 비어 있습니다.**
화면 위 날짜 막대에서 **◀ 어제** 를 누르거나 날짜를 골라 평일을 보면 됩니다.
지난 날짜를 보는 중이면 「지난 기록 보는 중」이 표시되고, 그날에 기록됩니다.

실행하면 **접속 주소가 바로 표시됩니다.**

```
  ──────────────────────────────────────────────────────────
   손잡고 마중 — 아이를 안전하게, 집으로
  ──────────────────────────────────────────────────────────
   선생님 기기   http://192.168.0.10:8000          ← 이 주소를 알려주세요
   이 PC         http://127.0.0.1:8000
   접속 안내·QR   http://127.0.0.1:8000/connect
  ──────────────────────────────────────────────────────────
   등록된 유치원  1곳 — 가득유치원
   로그인 PIN    0000  (설정에서 바꾸세요)
  ──────────────────────────────────────────────────────────
```

### 선생님들에게 주소 알려주기

`/connect` 화면(상단 **접속 안내** 탭)에서 한 번에 해결됩니다.

- **QR 코드** — 휴대폰 카메라로 찍으면 바로 열립니다
- **주소 복사 · 문자 내용 복사** — 카카오톡 단체방에 붙여넣으면 됩니다
- 휴대폰에서는 **공유하기** 로 카카오톡·문자에 바로 보낼 수 있습니다
- 주소가 여러 개면(유선·무선 함께 사용) 전부 보여줍니다

### 유치원 추가

원장이 `/signup` 에서 신청하면 **승인 대기** 상태가 되고, 운영자가 `/operator` 에서
승인하면 이용이 시작됩니다. 신청 시 반 6개·귀가 차수 5단계·학원 목록이 기본값으로
함께 만들어져, 승인 직후 빈 화면을 마주하지 않습니다.

## 공개 서버에서의 보안

### 계정과 세션
- 비밀번호는 **계정마다 다른 소금**으로 해시 (PBKDF2 24만회, 원문 저장 없음)
- 로그인 5회 실패 시 10분 잠금
- 아이디가 없든 비밀번호가 틀리든 **같은 문구** — 계정 존재 여부를 알리지 않음
- **비밀번호를 바꾸면 다른 기기의 로그인이 모두 끊깁니다** — 비밀번호가 샜을 때
  되찾는 유일한 방법입니다
- 세션 쿠키는 `HttpOnly` · `SameSite=Lax`, HTTPS 에서는 `Secure`
  (리버스 프록시의 `X-Forwarded-Proto` 를 함께 봅니다)

### 요청
- 모든 POST 에 **CSRF 토큰** — 남의 사이트가 「귀가 처리」를 대신 보내지 못합니다
- 주소로 넘어오는 **모든 id 는 내 유치원 것인지 확인**합니다.
  숫자만 바꿔 남의 유치원 반을 지우거나 아이를 처리할 수 없습니다
- 서명 이미지 크기 제한 — 큰 값으로 저장 공간을 채울 수 없습니다

### 감사 로그
- **모든 요청을 남깁니다** — 화면을 연 것까지. 누가·언제·무엇을·어디서
- **30일이 지나면 자동으로 지웁니다.** 서버가 뜰 때와 한 시간에 한 번 정리합니다.
  오래 쌓을수록 새어 나갔을 때의 피해만 커집니다
- 기록에 개인정보를 담지 않습니다 (원아 이름은 주소에 실리지 않습니다)
- `/health` 와 정적 파일은 기록하지 않습니다 — 기기가 10초마다 두드리는 주소입니다

### 개인정보
- 처리 결과 안내는 **주소가 아니라 쿠키**로 전달합니다.
  `?msg=김민준 귀가 처리` 처럼 실으면 **원아 이름이 서버 접속 로그에 그대로 남습니다**
- 임시 비밀번호도 같은 이유로 주소에 싣지 않습니다
- **보호자 연락처는 저장하되 화면에는 가려서** 보여줍니다 (`010-****-5678`).
  결석 확인 전화에는 필요하지만, 이름과 번호가 함께 떠 있으면 사진 한 장으로 새어 나갑니다
- 유치원 목록과 선생님 명단은 로그인 전에 드러나지 않습니다

### 배포 전 반드시

```powershell
# 세션 서명 키 — 이 값을 아는 사람은 남의 로그인을 만들어낼 수 있습니다
$env:MAJUNG_SECRET = "충분히 긴 임의의 문자열"
```

기본 키로 외부(`--host 0.0.0.0`)에 열면 **서버가 시작되지 않습니다.**

**HTTPS 는 필수입니다.** 없으면 비밀번호와 세션이 평문으로 오가 위의 대비가 모두
소용없습니다. 리버스 프록시(nginx 등)에서 인증서를 붙이고 `X-Forwarded-Proto` 를
전달하도록 설정하세요.

- `data/`, `*.db`, `*.xlsx` 는 **`.gitignore` 로 커밋이 차단**되어 있습니다.
  원아 이름과 보호자 정보가 저장소에 올라가지 않습니다.
- 저장소는 **비공개**로 유지해야 합니다.

## 원아 명부 등록

명부 관리는 선생님이 주도합니다. 원장이 **명부 엑셀** 화면에서:

1. **양식 내려받기** — 그 유치원의 반·귀가 차수·학원이 이미 채워져 있고,
   반 이름은 목록에서 고르게 되어 있어 오타가 나지 않습니다.
   **작성안내** 시트에 무엇을 적을지 정리되어 있습니다
2. 아이 한 명이 한 줄. 요일 칸에 그날의 귀가 방법을 적습니다
   (`1차 개별` · `1차 차량` · `학원(태권도)` · `돌봄` · 빈칸이면 정규 후 귀가)
3. 올리면 **미리보기**가 나옵니다. 잘못된 줄을 행 번호와 이유로 짚어주며,
   **「등록하기」를 누르기 전에는 아무것도 저장되지 않습니다**

기존 명부가 있으면 **추가 / 전체 교체**를 고르게 합니다.
올린 파일은 등록 직후 지워지고, 남은 것도 30분 뒤 정리됩니다.

## 구조

```
src/firstout/
├── main.py          서버 진입점 · 공통 화면 값 · 실행 배너
├── models.py        데이터 구조 (유치원별로 나뉨)
├── service.py       업무 규칙 (차수별 명단 계산)
├── net.py           접속 주소 찾기 · QR 코드
├── seed.py          유치원 생성 기본값 · 시연용 원아
├── security.py      PIN 해시 · 로그인 토큰
├── web/             화면별 경로
├── templates/       Jinja2 화면
└── static/          CSS · JS · 글꼴
```

`service.py` 가 이 프로그램의 핵심입니다. "주간 계획 + 오늘 출결" 에서
"오늘 차수별 명단" 을 만들어냅니다.
