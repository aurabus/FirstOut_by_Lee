# NAS 한 대로 홈페이지와 손잡고 마중 올리기 (DSM 방식)

처음 해보시는 분을 앞에 두고 쓴 문서입니다. **위에서부터 순서대로** 따라가시면 됩니다.
중간에 막히면 맨 아래 「문제가 생기면」을 보세요.

시간은 넉넉히 **두세 시간** 잡으시면 됩니다. 대부분은 기다리는 시간입니다.

---

## 0. 무엇을 만드는 것인가

지금은 이렇습니다.

```
   http (80)   ──→  맥미니 아파치  ──→  홈페이지
   https(443)  ──→  NAS          ──→  DSM 로그인 화면  ← 밖에 보이면 안 되는 것
   8043        ──→  NAS          ──→  DSM 로그인 화면  ← 이것도
```

이렇게 바꿉니다.

```
                인터넷
                  │  80·443 두 개만 열어 둡니다
             학교 고정 IP
                  │
        ┌─────────┴──────────────────────────────┐
        │  NAS                                    │
        │                                         │
        │   DSM 역방향 프록시  ← 문지기            │
        │      │                                  │
        │      ├─ www.aurabus.com    → site       │
        │      ├─ aurabus.com        → site       │
        │      └─ majung.aurabus.com → majung     │
        │                                         │
        │   DSM 관리 화면 ← 밖에서 못 들어옵니다   │
        └─────────────────────────────────────────┘
```

**중간에 남의 회사를 거치지 않습니다.** 원아 이름과 보호자 연락처가 오가는
서비스라 이 점이 중요합니다. 인증서는 DSM 이 무료로 발급받아 스스로 갱신합니다.

대신 **NAS 를 인터넷에 직접 내놓는 것**이므로, 9장의 잠그기를 반드시 하셔야 합니다.

### 낱말 몇 개

| 말 | 뜻 |
|---|---|
| **컨테이너** | 프로그램 한 벌을 상자에 담아 통째로 돌리는 것. 이 상자 둘이 NAS 에서 돕니다 |
| **Container Manager** | 그 상자를 돌리는 DSM 프로그램 |
| **역방향 프록시** | 문지기. 손님이 어느 주소로 왔는지 보고 알맞은 방으로 안내합니다 |
| **A 레코드** | 「이 주소는 이 IP 다」라고 적어두는 것 |
| **SSH** | 검은 화면으로 NAS 에 명령을 넣는 것. 무섭지 않습니다, 그냥 글자입니다 |

## 1. 준비물

- [ ] 시놀로지 NAS, **DSM 7.0 이상**
- [ ] 패키지 센터에 **Container Manager** 가 보일 것
      (DSM 6 이면 이름이 `Docker` 입니다. 아예 안 보이면 그 NAS 는 도커를 못 씁니다)
- [ ] `aurabus.com` 의 **DNS 관리 화면**에 들어갈 수 있을 것 (서브도메인을 추가해야 합니다)
- [ ] 공유기 관리 화면에 들어갈 수 있을 것 (포트포워딩을 고쳐야 합니다)
- [ ] 맥미니에 있는 홈페이지 파일

**지금 돌고 있는 홈페이지는 8장까지 건드리지 않습니다.** 중간에 잘못돼도
서비스가 끊기지 않습니다.

## 2. 홈페이지 파일을 `site/` 에 넣는다

맥미니의 웹 폴더를 통째로 가져와 이 저장소의 `site/` 폴더에 넣습니다.
무엇을 가져와야 하는지는 **[site/README.md](../site/README.md)** 에 목록으로 적어두었습니다.

가장 중요한 것 하나 — **`index.html` 이 있어야 합니다.** 이 파일이 없으면
`www.aurabus.com` 으로 들어왔을 때 아무것도 안 나옵니다.

넣으셨으면 윈도우에서 저장소에 올려둡니다.

```powershell
git add site
git commit -m "홈페이지 파일을 가져옴"
git push
```

## 3. 서브도메인을 만든다

`majung.aurabus.com` 을 새로 만듭니다. 지금 `aurabus.com` 의 네임서버가
데이콤(LG U+) 으로 되어 있으니, **도메인을 산 곳이나 DNS 를 관리하는 곳**에
로그인해서 **A 레코드**를 하나 추가합니다.

| 이름(호스트) | 종류 | 값 |
|---|---|---|
| `majung` | A | 학교에서 받은 고정 IP |

`www` 와 `aurabus.com` 은 이미 그 IP 를 가리키고 있으니 그대로 두시면 됩니다.

> **나중에 서브도메인을 더 만들 때도 똑같습니다.** 여기서 A 레코드를 하나 추가하고,
> 7장의 역방향 프록시 규칙을 하나 더 만들고, 6장에서 인증서에 그 주소를 넣으면 됩니다.
> 자세한 건 맨 아래 「서브도메인을 더 만들 때」에 정리해 두었습니다.

**바뀌는 데 보통 10분에서 한 시간쯤** 걸립니다. 확인은 윈도우 PowerShell 에서:

```powershell
nslookup majung.aurabus.com
```

학교 고정 IP 가 나오면 된 것입니다. 그동안 다음 단계를 진행하셔도 됩니다.

## 4. NAS 준비

### 4-1. Container Manager 를 설치한다

DSM → **패키지 센터** → `Container Manager` 검색 → 설치.

### 4-2. 자료가 쌓일 폴더를 만든다

**File Station** 에서 `docker` 공유 폴더 안에 `majung` 폴더를 만듭니다.

```
/volume1/docker/majung/
```

### 4-3. SSH 를 켠다

**제어판 → 터미널 및 SNMP → SSH 서비스 활성화** 체크 → 적용.

> 다 끝나면 이 체크를 꺼두셔도 됩니다. 어차피 9장에서 SSH 포트는 밖으로 열지 않습니다.

### 4-4. NAS 에 들어가 본다

윈도우 **PowerShell** 을 열고 (시작 → `powershell` 입력):

```powershell
ssh 관리자아이디@NAS주소
```

`NAS주소` 는 사무실 안에서라면 `192.168.x.x` 같은 것입니다. DSM 로그인할 때
쓰는 주소와 같습니다. 처음 들어가면 「계속하시겠습니까」를 묻는데 `yes` 를 칩니다.
비밀번호를 칠 때 **아무것도 안 보이는 게 정상**입니다. 그냥 치고 엔터를 누르세요.

### 4-5. 내 번호를 확인한다

들어가셨으면 이걸 칩니다.

```bash
id
```

```
uid=1026(aurabus) gid=100(users) ...
```

이렇게 나오면 **1026 과 100** 을 적어두세요. 이 번호가 안 맞으면
손잡고 마중이 자료를 못 쓰고 죽습니다.

## 5. 코드를 받고 띄운다

### 5-1. 코드를 받는다

NAS 에 들어간 그 검은 화면에서 이어서 칩니다.

```bash
cd /volume1/docker/majung
git clone https://github.com/aurabus/FirstOut_by_Lee.git app
cd app
ls
```

`Dockerfile`, `docker-compose.yml`, `site`, `src` 같은 것들이 보이면 된 것입니다.
`git: command not found` 라고 나오면 패키지 센터에서 **Git Server** 를 설치하고 다시 해보세요.

### 5-2. 세션 서명 키를 만든다

**윈도우 PowerShell 을 하나 더 열어서** (NAS 말고 내 PC 에서) 칩니다.

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

길쭉한 글자가 나옵니다. 복사해 둡니다.

> 이 값을 아는 사람은 남의 로그인을 만들어낼 수 있습니다. 카카오톡이나 메일로
> 보내지 마시고, 여기서 복사해 바로 붙여 넣으세요.

### 5-3. `.env` 파일을 채운다

NAS 화면으로 돌아와서:

```bash
cp .env.example .env
vi .env
```

`vi` 는 처음이면 낯섭니다. 이렇게 쓰시면 됩니다.

| 하고 싶은 것 | 누를 것 |
|---|---|
| 글자를 고치기 시작 | `i` (왼쪽 아래에 `-- INSERT --` 가 뜹니다) |
| 다 고쳤다 | `Esc` |
| 저장하고 나가기 | `Esc` 누른 뒤 `:wq` 치고 엔터 |
| 저장 안 하고 나가기 | `Esc` 누른 뒤 `:q!` 치고 엔터 |

채울 것은 이 넷입니다.

```
MAJUNG_SECRET=아까_복사한_긴_글자
MAJUNG_PUBLIC_URL=https://majung.aurabus.com
MAJUNG_UID=1026        ← 4-5 에서 본 번호
MAJUNG_GID=100         ← 4-5 에서 본 번호
```

다 채우셨으면 **이 파일을 나만 읽게** 잠급니다. 세션 서명 키가 들어 있습니다.

```bash
chmod 600 .env
```

### 5-4. 자료 폴더를 미리 만든다 ← 빠뜨리기 쉽습니다

```bash
mkdir -p data
```

**이 한 줄을 꼭 먼저 하세요.** 이 폴더가 없으면 도커가 대신 만드는데, 그때 주인이
`root` 가 되어 버립니다. 그러면 손잡고 마중이 자료를 쓰지 못하고
`Permission denied` 를 내며 계속 죽습니다.

지금처럼 내 손으로 만들면 주인이 나(4-5 에서 본 번호)가 되어 딱 맞습니다.

### 5-5. 띄운다

```bash
docker compose up -d --build
```

처음에는 손잡고 마중을 만드느라 몇 분 걸립니다. 글자가 죽 흐르는 것이 정상입니다.

**`docker: command not found` 라고 나오면** 앞에 `sudo` 를 붙여 보세요.

```bash
sudo docker compose up -d --build
```

**`docker compose` 는 없는데 `docker-compose` 는 있다고 나오면** (DSM 7.1 이하의
옛 Docker 패키지가 그렇습니다) 띄어쓰기 대신 붙임표를 쓰시면 됩니다.

```bash
sudo docker-compose up -d --build
```

이 문서의 나머지 `docker compose ...` 명령도 모두 같은 식으로 바꿔 쓰시면 됩니다.

### 5-6. NAS 안에서 잘 도는지 본다

```bash
docker compose ps
curl -s -o /dev/null -w "홈페이지 %{http_code}\n" http://127.0.0.1:8080/
curl -s http://127.0.0.1:8765/health
```

둘 다 `Up` 이고, `홈페이지 200` 과 `{"status":"ok", ...}` 가 나오면 성공입니다.

### 5-7. 운영자 계정을 한 번 만든다

유치원의 가입 신청을 승인하는 계정입니다. **딱 한 번만** 만듭니다.

```bash
docker compose run --rm majung firstout --operator 아이디:비밀번호 --host 127.0.0.1
```

`운영자 계정 생성: ...` 이라고 뜨면 **`Ctrl` + `C`** 로 빠져나옵니다.
계정은 이미 만들어졌습니다.

## 6. 인증서를 발급받는다

**HTTPS 는 필수입니다.** 없으면 비밀번호와 세션이 평문으로 오갑니다.

### 6-1. 먼저 80 포트를 NAS 로 돌린다

인증서를 받으려면 인증기관이 **80 포트로** 우리 서버를 확인합니다.
공유기 관리 화면 → **포트포워딩** 에서:

- **80 포트** → 맥미니로 가던 것 → **NAS 로 바꿉니다**
- **443 포트** → 이미 NAS 로 가고 있으면 그대로 둡니다

> 이 순간 홈페이지가 잠깐 안 보입니다. 8장까지 30분 안에 끝내시면 됩니다.
> 밤이나 주말에 하시는 편이 마음 편합니다.

### 6-2. 인증서를 받는다

DSM → **제어판 → 보안 → 인증서 → 추가 → 새 인증서 추가 → Let's Encrypt 에서 인증서 받기**

| 칸 | 넣을 값 |
|---|---|
| 도메인 이름 | `aurabus.com` |
| 이메일 | 받을 수 있는 주소 |
| **주체 대체 이름** | `www.aurabus.com;majung.aurabus.com` |

**주체 대체 이름 칸이 핵심입니다.** 여기에 적은 주소들이 한 장의 인증서에 함께 들어갑니다.
세미콜론(`;`)으로 구분합니다. 서브도메인을 나중에 더 만들면 여기에 추가하면 됩니다.

받고 나면 **제어판 → 보안 → 인증서 → 설정** 에서 세 주소가 모두
이 인증서를 쓰도록 지정합니다. DSM 이 만료 전에 알아서 갱신합니다.

## 7. 문지기를 세운다 (역방향 프록시)

DSM → **제어판 → 로그인 포털 → 고급 → 역방향 프록시 → 생성**

### 7-1. 홈페이지 (www)

| 칸 | 값 |
|---|---|
| 설명 | `홈페이지 www` |
| 원본 · 프로토콜 | `HTTPS` |
| 원본 · 호스트 이름 | `www.aurabus.com` |
| 원본 · 포트 | `443` |
| 대상 · 프로토콜 | `HTTP` |
| 대상 · 호스트 이름 | `localhost` |
| 대상 · 포트 | `8080` |

만들기 전에 **사용자 지정 헤더** 탭으로 가서 **생성 → WebSocket** 을 누릅니다.
그리고 아래 두 줄이 있는지 확인하고, 없으면 직접 추가합니다.

| 헤더 이름 | 값 |
|---|---|
| `X-Forwarded-Proto` | `$scheme` |
| `X-Forwarded-For` | `$proxy_add_x_forwarded_for` |

### 7-2. 홈페이지 (www 없이)

7-1 과 똑같이 만들되 **호스트 이름만 `aurabus.com`** 으로 합니다.

### 7-3. 손잡고 마중

| 칸 | 값 |
|---|---|
| 설명 | `손잡고 마중` |
| 원본 · 호스트 이름 | `majung.aurabus.com` |
| 원본 · 포트 | `443` |
| 대상 · 포트 | **`8765`** |

나머지는 같습니다. **사용자 지정 헤더 두 줄을 여기에도 꼭 넣으세요.**
이게 없으면 감사 로그의 접속지가 전부 NAS 주소로 뭉갭니다.

### 7-4. `http://` 로 들어온 손님을 `https://` 로 보낸다

세 규칙 모두 **원본 프로토콜을 `HTTPS`(443)로만** 만들었습니다. 그러면
`http://www.aurabus.com` 처럼 **`http://` 를 붙여 들어온 손님**은 이 규칙에 걸리지
않고 DSM 자기 화면으로 떨어집니다. 예전 즐겨찾기나 명함에 적힌 주소가 그렇습니다.

DSM → **제어판 → 로그인 포털 → DSM** 에서
**「HTTP 연결을 HTTPS 로 자동 리디렉션」** 을 켜면 됩니다.

> **80 포트에 역방향 프록시 규칙을 만들지 마세요.** 그러고 싶어지지만 그러면
> 인증서 갱신이 깨집니다. 인증기관이 `http://주소/.well-known/...` 로 확인하는데,
> 그 주소가 우리 컨테이너로 넘어가 버려 확인에 실패합니다.
> 80 포트는 DSM 에게 맡겨 두는 것이 맞습니다.

켠 뒤 확인합니다 (윈도우 PowerShell).

```powershell
curl.exe -sI http://www.aurabus.com/ | Select-String "HTTP/|Location"
```

`301` 이나 `302` 가 나오고 `Location` 이 `https://www.aurabus.com/` 이면 잘 된 것입니다.

만약 `Location` 이 `:8043` 같은 **포트가 붙은 주소**로 나오면 이 방법은 이 DSM 판에서는
안 맞는 것입니다. 그때는 켠 것을 다시 끄고 이렇게 하세요.

- 명함·인쇄물·검색등록에 적힌 주소를 `https://` 로 바꿉니다
- 요즘 브라우저는 주소만 치면 `https` 부터 시도하므로 대부분은 그냥 열립니다
- 홈페이지 안의 링크는 모두 상대경로라 문제없습니다

## 8. 밖에서 확인한다

**휴대폰에서 와이파이를 끄고** (사무실 밖에서 보는 것과 같게 만들려는 것입니다)
주소를 쳐봅니다.

- `https://www.aurabus.com` → 홈페이지가 뜨고 **자물쇠가 보여야** 합니다
- `https://aurabus.com` → 홈페이지
- `https://majung.aurabus.com` → 손잡고 마중 로그인 화면
- `http://www.aurabus.com` (https 없이) → 홈페이지로 넘어가야 합니다 (7-4)

넷 다 되면 갈아타기 끝입니다. 맥미니는 이제 꺼두셔도 됩니다.

**한 가지만 더 확인하세요 — 접속지가 제대로 남는지.** 손잡고 마중에 로그인한 뒤
**감사 로그**를 열어 방금 내 접속 기록의 「접속지」를 봅니다. 거기에 NAS 주소나
`172.x.x.x` 같은 것이 아니라 **내 실제 주소**가 찍혀 있어야 합니다.
아니면 7장의 사용자 지정 헤더 두 줄이 빠진 것입니다.

---

## 9. NAS 를 잠근다 ← 가장 중요한 장

NAS 를 인터넷에 직접 내놓기로 하셨으니, 이 장은 **선택이 아닙니다.**
시놀로지 관리 화면은 랜섬웨어가 가장 먼저 훑는 대상입니다.

### 9-1. 관리 포트를 밖으로 열지 않는다

공유기 **포트포워딩**에 **80 과 443 만** 남기고 나머지를 **전부 지웁니다.**
특히 이것들이 있으면 반드시 지우세요.

| 포트 | 무엇 |
|---|---|
| `8043` · `8033` | **지금 열려 있습니다.** DSM 관리 화면입니다 |
| `5000` · `5001` | DSM 관리 화면 |
| `22` | SSH |

지운 뒤 휴대폰(와이파이 끈 상태)에서 확인합니다.

- `https://aurabus.com:8043` → **안 열려야 합니다**
- `https://aurabus.com:5001` → **안 열려야 합니다**

### 9-2. DSM 안에서도 잠근다

| 어디 | 무엇을 |
|---|---|
| 제어판 → 보안 → 계정 | **자동 차단** 켜기 (10분에 5번 틀리면 차단) |
| 제어판 → 보안 → 계정 | **계정 보호** 켜기 |
| 제어판 → 보안 → 보호 | **DoS 보호** 켜기 |
| 제어판 → 보안 → 방화벽 | 켜고, **80·443 만** 모든 곳에서 허용. 나머지는 사내망(192.168.x.x)만 |
| 제어판 → 사용자 → 고급 | 기본 `admin` 계정 **사용 안 함**. 다른 이름의 관리자를 쓰세요 |
| 개인 → 계정 | 관리자 계정에 **2단계 인증** 켜기 |
| 제어판 → 업데이트 및 복원 | DSM **자동 업데이트** 켜기 |

### 9-3. 관리는 어떻게 하나

**테일스케일**로 들어가시면 됩니다. 이미 쓰고 계시니 NAS 에도 설치해 두세요.
그러면 어디서든 테일스케일 주소로 DSM 에 들어갈 수 있고, 인터넷에는
80·443 두 개 말고 아무것도 열리지 않습니다.

---

## 10. 자료를 지킨다

NAS 한 대로 돌리기로 하셨으니 이 장도 **건너뛰지 마세요.** 한 대가 멈추면 둘 다 멈춥니다.

### 10-1. 백업 한 벌은 반드시 바깥으로

손잡고 마중은 매일 자기 사본을 `data/backup/` 에 떨궈 둡니다 (30일치).
그런데 **서버와 백업이 같은 NAS 에 있습니다.** 그 장비가 죽으면 둘 다 없어집니다.

**Hyper Backup** 으로 `/volume1/docker/majung/data` 를 다른 곳으로 한 벌 더 보냅니다.
다른 NAS, 외장 디스크 중 아무거나 좋습니다. 하루 한 번이면 넉넉합니다.

원아 이름과 보호자 연락처가 든 자료이므로 **백업에도 암호를 겁니다.**

### 10-2. UPS 를 답니다

정전으로 NAS 가 갑자기 꺼지면 데이터베이스가 깨질 수 있습니다.
UPS 를 USB 로 물리면 **제어판 → 하드웨어 및 전원 → UPS** 에서 인식하고,
정전 때 NAS 가 스스로 안전하게 내려갑니다. 10만 원대면 충분합니다.

가장 값싼 보험입니다.

## 11. 평소 관리

```bash
cd /volume1/docker/majung/app

```

**홈페이지와 손잡고 마중이 함께 갱신됩니다.** 자료(`data/`)는 그대로 남습니다.

| 하는 일 | 명령 |

| 기록 보기 | `docker compose logs -f --tail=100 majung` |


## 서브도메인을 더 만들 때

예를 들어 `demo.aurabus.com` 을 추가한다면 **세 군데**를 손보면 됩니다.

1. **DNS** — A 레코드 추가 (`demo` → 학교 고정 IP)
2. **인증서** — 제어판 → 보안 → 인증서 → 그 인증서 편집 →
   주체 대체 이름에 `;demo.aurabus.com` 추가 → 다시 발급
3. **역방향 프록시** — 규칙 하나 더 만들기 (7장과 같은 방식, 대상 포트만 다르게)

새 프로그램을 하나 더 올린다면 `docker-compose.yml` 에 서비스를 추가하고
`127.0.0.1:다른포트` 로 열어준 뒤, 그 포트를 3번에서 가리키면 됩니다.

---

## 학교에서 받은 IP 가 바뀌면

이 방식은 그 IP 에 매여 있습니다. 바뀌면 **DNS 의 A 레코드 세 개**
(`aurabus.com` · `www` · `majung`) 를 새 IP 로 고치시면 됩니다.
바뀐 것이 퍼지는 데 10분에서 한 시간쯤 걸립니다.

미리 대비하시려면 DNS 관리 화면에서 **TTL 을 300초**(5분)로 낮춰두세요.
그러면 바꿨을 때 훨씬 빨리 퍼집니다.

## 문제가 생기면

**홈페이지 자리에 「홈페이지 파일이 아직 없습니다」가 뜬다**
→ `site/` 에 진짜 파일을 안 넣으신 것입니다. 2장으로.

**인증서 발급이 실패한다**
→ 80 포트가 NAS 로 오고 있는지 봅니다 (6-1). 그리고 `majung.aurabus.com` 의
   A 레코드가 퍼졌는지 `nslookup` 으로 확인합니다. 안 퍼졌으면 인증에 실패합니다.

**주소를 쳤는데 DSM 로그인 화면이 뜬다**
→ 그 주소의 역방향 프록시 규칙이 없는 것입니다. 규칙에 적은 호스트 이름의
   철자를 확인하세요. 규칙이 없는 주소는 DSM 이 자기 화면을 보여줍니다.

**「안전하지 않은 사이트」 경고가 뜬다**
→ 인증서에 그 주소가 안 들어간 것입니다. 6-2 의 주체 대체 이름을 확인하세요.

**손잡고 마중이 계속 죽는다 (`Restarting` 이 반복된다)**
→ `docker compose logs majung` 을 봅니다.
   - `Permission denied` → 자료 폴더의 주인이 안 맞습니다. 5-4 의 `mkdir -p data` 를
     빠뜨렸거나, `.env` 의 번호가 4-5 에서 본 것과 다른 경우입니다. 이렇게 고칩니다.

     ```bash
     docker compose down
     sudo chown -R $(id -u):$(id -g) data
     vi .env                       # UID·GID 를 `id` 가 알려준 번호로
     docker compose up -d --build
     ```
   - `MAJUNG_SECRET` 이야기가 나오면 → `.env` 에 키를 안 넣으신 것입니다

**감사 로그의 접속지가 전부 같은 주소로 나온다**
→ 7장의 **사용자 지정 헤더 두 줄**이 빠진 것입니다. 규칙을 다시 열어 넣어주세요.
   `.env` 의 `MAJUNG_PROXY_HOPS` 가 `1` 인지도 확인합니다.

**귀가 시각이 9시간 어긋난다**
→ `docker compose exec majung date` 를 쳐서 한국 시각이 나오는지 봅니다.

대여섯 곳을 넘으면** 손잡고 마중만 국내 클라우드(네이버 클라우드·카카오 클라우드 등)로
옮기시는 것을 권합니다. 국내에 두면 국외 이전 문제도 생기지 않습니다.
