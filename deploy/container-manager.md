# Container Manager 화면에서 손으로 올려 보기

검은 화면(SSH) 없이, **DSM 화면만으로** 손잡고 마중이 도는지 확인하는 길입니다.
「도커가 NAS 에서 제대로 도는가」만 먼저 보는 것이 목적이라, 여기서는
도메인도 인증서도 자료 폴더도 붙이지 않습니다. 20분이면 됩니다.

잘 돌면 그때 [README.md](README.md) 로 넘어가 제대로 세우시면 됩니다.

---

## 1. 이미지 파일을 받는다

개발용 PC 에는 도커가 없어서 GitHub 이 대신 만들어 줍니다.

1. `https://github.com/aurabus/FirstOut_by_Lee` 로 갑니다
2. 위쪽 **Actions** 탭 → 왼쪽에서 **도커 이미지 만들기**
3. 오른쪽 **Run workflow** 단추 → 초록 **Run workflow**
4. 3~5분 기다립니다. 목록에 새 줄이 생기고 노란 점이 초록 체크로 바뀝니다
5. 그 줄을 눌러 들어가면 맨 아래 **Artifacts** 에 `majung-image` 가 있습니다.
   눌러서 내려받습니다
6. 받아진 `majung-image.zip` 을 풀면 **`majung.tar`** 이 나옵니다 (300MB 안팎)

> 만드는 김에 GitHub 이 한 번 돌려보고 확인까지 합니다 — 화면이 그려지는지,
> 시각이 한국으로 맞는지. 초록 체크면 그 확인까지 통과한 것입니다.

## 2. Container Manager 에 올린다

DSM → **Container Manager** → 왼쪽 **이미지** → **추가** → **파일에서 추가**

`majung.tar` 을 고릅니다. 올리는 데 몇 분 걸립니다.
끝나면 이미지 목록에 **`majung:latest`** 가 보입니다.

## 3. 컨테이너를 만든다

이미지 목록에서 `majung:latest` 를 고르고 **실행** 을 누릅니다.

### 3-1. 일반 설정

| 칸 | 값 |
|---|---|
| 컨테이너 이름 | `majung-시험` |
| 자동 재시작 활성화 | 꺼둡니다 (시험이니까) |

### 3-2. 포트 설정

| 로컬 포트 | 컨테이너 포트 |
|---|---|
| `8765` | `8000` |

「자동」으로 되어 있으면 `8765` 로 바꿔주세요. 뒤에서 이 번호로 들어갑니다.

### 3-3. 환경 변수 ← 이걸 빠뜨리면 안 뜹니다

**고급 설정 → 환경** 에서 아래 하나를 반드시 넣습니다.

| 변수 | 값 |
|---|---|
| `MAJUNG_SECRET` | 아무도 모르는 긴 글자 |

이 값이 없으면 서버가 **일부러 시작하지 않습니다.** 이 값을 아는 사람은 남의
로그인 세션을 만들어낼 수 있어서, 기본값인 채로 밖에 열리는 것을 막아둔 것입니다.

만드는 법 (윈도우 PowerShell 한 줄):

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

**값을 꼭 채우세요.** 이름만 넣고 값을 비워두면 안 넣은 것과 같습니다.
32자 넘게 두시길 권합니다.

> 지금은 시험이니 아무 긴 글자라도 됩니다. 다만 **진짜로 쓸 때는 반드시 새로**
> 만드세요. 시험용으로 쓴 값을 그대로 두면 안 됩니다.

### 이미 만들어서 계속 꺼진다면

**환경 변수는 컨테이너를 만들 때 정해집니다.** 이미 만든 뒤에 넣으려면
그 컨테이너를 **지우고 다시 만드셔야** 하는 경우가 많습니다.
(이미지는 그대로 있으니 다시 올릴 필요는 없습니다.)

로그에 이렇게 나오면 이 경우입니다.

```
세션 서명 키(MAJUNG_SECRET)가 정해지지 않았습니다.
이대로 외부에 열면 남의 로그인 세션을 만들어낼 수 있어 시작하지 않습니다.
```

### 3-4. 저장 공간 — 이번에는 붙이지 않습니다

**볼륨을 붙이지 마세요.** 원아 자료는 컨테이너 안에만 잠깐 있다가 지워집니다.
시험이니 그게 편합니다.

> 폴더를 붙이면 **주인 번호가 안 맞아 곧바로 죽습니다.** 이미지는 1000번으로
> 도는데 시놀로지 계정은 보통 1026 같은 다른 번호라서 그렇습니다.
> 제대로 세울 때는 `docker-compose.yml` 이 `user:` 로 그 번호를 맞춰줍니다
> ([README.md](README.md) 5장).

만들고 **실행**합니다.

## 4. 들어가 본다

브라우저에서:

```
http://NAS주소:8765/
```

`NAS주소` 는 DSM 에 들어갈 때 쓰는 그 주소입니다 (`192.168.x.x` 같은 것).

**손잡고 마중 로그인 화면**이 뜨면 성공입니다. 도커가 NAS 에서 잘 돕니다.

## 5. 로그인까지 해보려면

운영자 계정을 하나 만들어야 합니다. Container Manager 에서
그 컨테이너를 고르고 **터미널** 탭 → **생성** → `bash` 를 누른 뒤:

```bash
firstout --operator 아이디:비밀번호 --host 127.0.0.1
```

`운영자 계정 생성: ...` 이 뜨면 `Ctrl` + `C` 로 빠져나옵니다.
이제 아까 그 주소에서 그 아이디로 로그인됩니다.

---

## 잘 안 될 때

**컨테이너가 켜지자마자 꺼진다**
→ 그 컨테이너의 **로그** 탭을 봅니다.
   `MAJUNG_SECRET` 이야기가 나오면 3-3 을 빠뜨린 것입니다.

**화면이 안 열린다**
→ 포트가 `8765` 로 되어 있는지, 컨테이너가 「실행 중」인지 봅니다.
   NAS 방화벽을 켜두셨다면 8765 가 사내망에서 허용되는지도요.

**Permission denied 가 보인다**
→ 3-4 에서 폴더를 붙이신 것입니다. 떼고 다시 만들어 보세요.
