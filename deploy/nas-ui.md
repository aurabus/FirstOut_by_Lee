# 검은 화면 없이 — DSM 화면만으로 NAS 에 올리기

SSH 도 명령어도 쓰지 않습니다. **DSM 웹 화면에서 눌러서만** 진행합니다.
공유기는 5장에 가서야 건드립니다. 그때까지는 지금 홈페이지가 그대로 돌아갑니다.

두 시간쯤 잡으시면 넉넉합니다.

---

## 준비물 — 내 PC 에 있는 파일 두 개

| 파일 | 어디에 있나 | 무엇 |
|---|---|---|
| `majung.tar` | `C:\Users\NBI\Aurabus Dev\dist\` | 손잡고 마중 프로그램 (72MB) |
| `aurabus-site.zip` | `C:\Users\NBI\Aurabus Site\dist\` | 홈페이지 파일 한 묶음 (5.5MB) |

없으면 각 폴더에서 **`make-image.bat`** 을 두 번 누르시면 다시 만들어집니다.

그리고 **세션 서명 키**를 하나 만들어 메모장에 붙여 두세요. PowerShell 에서:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

길쭉한 글자가 나옵니다. 3장에서 씁니다.

## 1. 폴더를 만들고 홈페이지를 올린다 (File Station)

DSM 에 로그인해서 **File Station** 을 엽니다.

### 1-1. 폴더 만들기

`docker` 공유 폴더 안에 폴더 **둘**을 만듭니다. 위쪽 **만들기 → 폴더 만들기**.

```
docker/majung          ← 손잡고 마중의 자료가 쌓일 곳
docker/aurabus-site    ← 홈페이지 파일이 들어갈 곳
```

그리고 `majung` 안에 **`data`** 폴더를 하나 더 만듭니다.

```
docker/majung/data
```

### 1-2. `data` 폴더에 쓸 수 있게 해준다 ← 빠뜨리면 안 됩니다

`docker/majung/data` 를 **오른쪽 클릭 → 속성 → 권한** 탭으로 갑니다.

**만들기** 를 눌러 이렇게 넣습니다.

| 칸 | 고를 것 |
|---|---|
| 사용자 또는 그룹 | **Everyone** |
| 유형 | 허용 |
| 적용 대상 | 이 폴더, 하위 폴더 및 파일 |
| 권한 | **읽기** 와 **쓰기** 모두 체크 |

확인 → 저장.

> **왜 이걸 하나** — 손잡고 마중은 컨테이너 안에서 「1000번 사용자」로 돕니다.
> 시놀로지 계정 번호와 다르기 때문에, 이 권한을 안 주면 자료를 쓰지 못하고
> **컨테이너가 켜지자마자 계속 꺼집니다.** 로그에 `Permission denied` 가 뜹니다.

### 1-3. 홈페이지 파일 올리기

`docker/aurabus-site` 폴더로 들어간 뒤, 위쪽 **업로드 → 업로드 - 건너뛰기** 로
**`aurabus-site.zip`** 을 올립니다. 5.5MB 라 금방 끝납니다.

올라온 zip 파일을 **오른쪽 클릭 → 압축 풀기 → 여기에 압축 풀기**.

풀고 나면 이렇게 되어야 합니다.

```
docker/aurabus-site/
├── public/          ← 화면 파일들 (main.html, css, images ...)
└── nginx.conf
```

zip 파일은 이제 지우셔도 됩니다.

> `public` 폴더 안에 또 `public` 이 있으면 한 겹 잘못 풀린 것입니다.
> 안쪽 것을 밖으로 꺼내 주세요.

## 2. 홈페이지를 띄운다 (Container Manager)

**Container Manager** 를 엽니다.

### 2-1. nginx 이미지 받기

왼쪽 **레지스트리** → 위 검색창에 **`nginx`** → 맨 위의 **nginx** (공식) 선택
→ 위쪽 **다운로드** → 태그는 **`alpine`** 을 고릅니다.

작은 이미지라 1~2분이면 받아집니다. 왼쪽 **이미지** 에서 `nginx:alpine` 이
보이면 된 것입니다.

### 2-2. 컨테이너 만들기

**이미지** 목록에서 `nginx:alpine` 을 고르고 **실행**.

**일반 설정**

| 칸 | 값 |
|---|---|
| 컨테이너 이름 | `aurabus-site` |
| 자동 재시작 활성화 | **켭니다** |

**고급 설정 → 포트 설정**

| 로컬 포트 | 컨테이너 포트 | 유형 |
|---|---|---|
| `8080` | `80` | TCP |

**고급 설정 → 저장소** — **폴더 추가** 를 두 번 눌러 둘을 넣습니다.

| 파일/폴더 | 마운트 경로 | 쓰기 가능 |
|---|---|---|
| `docker/aurabus-site/public` | `/usr/share/nginx/html` | **끕니다** (읽기 전용) |
| `docker/aurabus-site/nginx.conf` | `/etc/nginx/conf.d/default.conf` | **끕니다** (읽기 전용) |

> 두 번째 것은 **폴더가 아니라 파일**입니다. 「파일 추가」 쪽으로 고르셔야 합니다.

만들고 **실행**합니다.

### 2-3. 확인

브라우저에서:

```
http://192.168.100.10:8080/
```

**아우라버스 홈페이지**가 뜨면 성공입니다.

## 3. 손잡고 마중을 띄운다 (Container Manager)

### 3-1. 이미지 올리기

왼쪽 **이미지** → **추가 → 파일에서 추가** → `majung.tar` 를 고릅니다.
72MB 라 몇 분 걸립니다. 끝나면 목록에 **`majung:latest`** 가 보입니다.

### 3-2. 컨테이너 만들기

`majung:latest` 를 고르고 **실행**.

**일반 설정**

| 칸 | 값 |
|---|---|
| 컨테이너 이름 | `majung` |
| 자동 재시작 활성화 | **켭니다** |

**고급 설정 → 포트 설정**

| 로컬 포트 | 컨테이너 포트 | 유형 |
|---|---|---|
| `8765` | `8000` | TCP |

**고급 설정 → 저장소** — **폴더 추가**

| 폴더 | 마운트 경로 | 쓰기 가능 |
|---|---|---|
| `docker/majung/data` | `/data` | **켭니다** |

**고급 설정 → 환경** — **추가** 를 눌러 셋을 넣습니다.

| 변수 | 값 |
|---|---|
| `MAJUNG_SECRET` | 준비물에서 만든 그 긴 글자 |
| `MAJUNG_PUBLIC_URL` | `https://majung.aurabus.com` |
| `MAJUNG_PROXY_HOPS` | `1` |

> **`MAJUNG_SECRET` 의 값을 꼭 채우세요.** 이름만 넣고 비워두면 안 넣은 것과
> 같아서 서버가 일부러 시작하지 않습니다.
>
> 환경 변수는 **컨테이너를 만들 때 정해집니다.** 나중에 고치려면 컨테이너를
> 지우고 다시 만드는 편이 확실합니다 (이미지는 그대로 있습니다).

만들고 **실행**합니다.

### 3-3. 확인

```
http://192.168.100.10:8765/
```

**손잡고 마중 로그인 화면**이 뜨면 성공입니다.

안 뜨면 그 컨테이너를 골라 **로그** 탭을 봅니다.

| 로그에 보이는 것 | 뜻 |
|---|---|
| `MAJUNG_SECRET ... 정해지지 않았습니다` | 3-2 의 환경 변수를 빠뜨렸습니다 |
| `Permission denied` | 1-2 의 폴더 권한을 빠뜨렸습니다 |

### 3-4. 유치원 자리를 만든다

컨테이너 `majung` 을 고르고 **터미널** 탭 → **생성** → **bash** 를 누릅니다.
검은 칸이 하나 열리는데, 거기에 이 한 줄을 붙여 넣고 엔터를 칩니다.

```
firstout --setup-only --operator admin:1234 --open-kinder "주덕화곡초등학교 병설유치원" --admin "지민희:jimin:1234"
```

이렇게 나오면 됩니다.

```
  운영자 계정 생성: admin
  유치원 개설: 주덕화곡초등학교 병설유치원
  총괄 관리자: 지민희 (jimin)
  준비를 마쳤습니다. 서버는 띄우지 않았습니다.
```

이제 `http://192.168.100.10:8765/` 에서 **`admin` / `1234`** 로 들어가집니다.
들어가면 곧바로 비밀번호를 새로 정하라고 나옵니다 — 그게 정상입니다.

## 4. 문지기를 세운다 (역방향 프록시)

**제어판 → 로그인 포털 → 고급 → 역방향 프록시** 로 갑니다.
**생성** 을 눌러 **세 개**를 만듭니다.

> **세 개를 다 만드셔야 합니다.** 홈페이지는 `www` 로 들어온 손님을
> `aurabus.com` 으로 되돌려 보냅니다. 그래서 **`aurabus.com` 규칙(②)이 없으면**
> www 로 들어온 사람도 결국 갈 곳을 잃습니다 — 실제로 그렇게 막혔습니다.

### 규칙 ① 홈페이지 (aurabus.com) ← 이게 진짜 홈페이지 주소입니다

| 칸 | 값 |
|---|---|
| 설명 | `홈페이지` |
| 원본 · 프로토콜 | **HTTPS** |
| 원본 · 호스트 이름 | **`aurabus.com`** (www 없이) |
| 원본 · 포트 | `443` |
| 대상 · 프로토콜 | **HTTP** |
| 대상 · 호스트 이름 | `localhost` |
| 대상 · 포트 | **`8080`** |

저장하기 전에 위쪽 **사용자 지정 헤더** 탭 → **생성 → WebSocket** 을 누릅니다.
그리고 아래 두 줄이 있는지 보고, 없으면 **생성** 으로 직접 넣습니다.

| 헤더 이름 | 값 |
|---|---|
| `X-Forwarded-Proto` | `$scheme` |
| `X-Forwarded-For` | `$proxy_add_x_forwarded_for` |

### 규칙 ② 홈페이지 (www)

①과 똑같이 만들되 **호스트 이름만 `www.aurabus.com`**.
이 규칙은 www 로 들어온 손님을 ①로 넘겨주는 몫입니다.

### 규칙 ③ 손잡고 마중

| 칸 | 값 |
|---|---|
| 설명 | `손잡고 마중` |
| 원본 · 호스트 이름 | `majung.aurabus.com` |
| 원본 · 포트 | `443` |
| 대상 · 포트 | **`8765`** |

나머지는 같습니다. **헤더 두 줄을 여기에도 꼭 넣으세요.**
이게 없으면 감사 로그의 접속지가 전부 NAS 주소로 뭉갭니다.

## 5. 공유기를 건드리기 전에 — 내 PC 로 전체 길 확인

도메인은 아직 맥미니를 가리킵니다. **내 PC 만 잠깐 NAS 를 보도록** 속여서
전체 길이 제대로 이어졌는지 봅니다.

1. 시작 버튼 → `메모장` 입력 → **오른쪽 클릭 → 관리자 권한으로 실행**
2. **파일 → 열기** → 아래 주소를 그대로 붙여 넣고 엽니다
   (파일 형식을 **모든 파일** 로 바꿔야 보입니다)

```
C:\Windows\System32\drivers\etc\hosts
```

3. 맨 아래에 세 줄을 더하고 저장합니다

```
192.168.100.10  aurabus.com
192.168.100.10  www.aurabus.com
192.168.100.10  majung.aurabus.com
```

4. 브라우저에서 열어 봅니다. **인증서 경고가 뜨는 게 정상입니다**
   (아직 인증서를 안 받았으니까요) — 「고급 → 계속」으로 넘어갑니다

| 주소 | 떠야 할 것 |
|---|---|
| `https://www.aurabus.com` | 아우라버스 홈페이지 |
| `https://majung.aurabus.com` | 손잡고 마중 로그인 화면 |

**여기서 제대로 갈리면 NAS 쪽은 다 끝난 것입니다.**

5. 확인이 끝나면 **그 세 줄을 지우고 저장하세요.** 그대로 두면 나중에
   밖에서 안 되는 것을 눈치채지 못합니다

## 6. 이제 공유기를 바꾼다

공유기 관리 화면 → **포트포워딩**.

| 포트 | 어디로 |
|---|---|
| `80` | **NAS (192.168.100.10)** |
| `443` | **NAS (192.168.100.10)** |
| **그 밖의 모든 것** | **지웁니다** |

**`8043` 은 반드시 지우세요.** 지금 DSM 관리 화면이 인터넷에 열려 있습니다.
`5000` · `5001` · `9292`(SSH) 도 열려 있으면 함께 지웁니다.

이 순간부터 맥미니는 쓰이지 않습니다. 꺼두셔도 됩니다.

## 7. 인증서를 받는다

**제어판 → 보안 → 인증서 → 추가 → 새 인증서 추가 → Let's Encrypt 에서 인증서 받기**

| 칸 | 값 |
|---|---|
| 도메인 이름 | `aurabus.com` |
| 이메일 | 받을 수 있는 주소 |
| **주체 대체 이름** | `www.aurabus.com;majung.aurabus.com` |

**주체 대체 이름 칸이 핵심입니다.** 세미콜론(`;`)으로 구분해 적은 주소들이
한 장의 인증서에 함께 들어갑니다.

받은 뒤 **제어판 → 보안 → 인증서 → 설정** 에서 세 주소가 모두 이 인증서를
쓰도록 지정합니다. 이제 경고 없이 자물쇠가 보입니다.
DSM 이 만료 전에 알아서 갱신합니다.

> 발급이 실패하면 6장의 **80 포트**가 NAS 로 오고 있는지 다시 보세요.
> 인증기관이 그 포트로 우리 서버를 확인합니다.

## 9. 마지막으로 — 자료를 지킨다

### 백업 한 벌은 바깥으로

손잡고 마중은 매일 자기 사본을 `docker/majung/data/backup/` 에 떨궈 둡니다.
그런데 **서버와 백업이 같은 NAS 에 있습니다.** 그 장비가 죽으면 둘 다 없어집니다.

**Hyper Backup** 으로 `docker/majung/data` 를 다른 곳으로 한 벌 더 보냅니다.
하루 한 번이면 넉넉하고, 원아 이름과 보호자 연락처가 든 자료이므로
**백업에도 암호를 겁니다.**

### DSM 을 잠근다

| 어디 | 무엇을 |
|---|---|
| 제어판 → 보안 → 계정 | **자동 차단** 켜기 |
| 제어판 → 보안 → 보호 | **DoS 보호** 켜기 |
| 제어판 → 사용자 → 고급 | 기본 `admin` 계정 **사용 안 함** |
| 개인 → 계정 | 관리자 계정에 **2단계 인증** |
| 제어판 → 업데이트 및 복원 | **자동 업데이트** 켜기 |

### UPS

정전으로 갑자기 꺼지면 데이터베이스가 깨질 수 있습니다. USB 로 물리면
**제어판 → 하드웨어 및 전원 → UPS** 에서 인식하고, 정전 때 스스로 안전하게
내려갑니다. 가장 값싼 보험입니다.

## 나중에 새 버전을 올릴 때

이 방식(이미지를 손으로 올리는 방식)에서는 이렇게 합니다.

1. 내 PC 에서 `make-image.bat` 을 눌러 새 `majung.tar` 을 만듭니다
2. Container Manager → **컨테이너** → `majung` **중지 → 삭제**
3. **이미지** → 옛 `majung:latest` **삭제**
4. **추가 → 파일에서 추가** → 새 `majung.tar`
5. 3-2 대로 컨테이너를 다시 만듭니다 (자료는 `data` 폴더에 그대로 남아 있습니다)

홈페이지는 더 간단합니다 — `docker/aurabus-site/public` 안의 파일만 바꾸면
새로고침으로 바로 반영됩니다. 컨테이너를 다시 띄울 필요도 없습니다.

> 이 되풀이가 번거로워지면 그때 저장소를 받아 쓰는 방식([README.md](README.md))으로
> 옮기시면 됩니다. 그러면 `git pull` 한 줄로 끝납니다.
